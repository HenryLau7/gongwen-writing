# 公文写作 Skill 设计文档

## 概述

**目标：** 创建一个 Claude Code skill，能够将用户输入的普通文本、Word文档或PDF文档改写/撰写为符合中国党政机关公文规范的正式文本。

**方案：** 纯 Prompt Skill — 单个 SKILL.md 文件，通过精心设计的prompt指导Claude完成公文改写，利用已有工具处理文件读写。

**安装目标：** 可发布的 skill 包。

---

## 架构

### 文件结构

```
gongwen-writing/
  SKILL.md          # 主skill文件（流程 + 公文规范 + 红线规则）
  CLAUDE.md         # 项目说明
```

### 依赖的已有能力

| 能力 | 用途 |
|------|------|
| `Read` 工具 | 读取纯文本文件 |
| `office-mcp` skill | 读取 Word/PDF 文件内容 |
| `word-document-processor` skill | 导出为 Word 文档时使用（创建和格式化） |

---

## Skill 元信息

```yaml
name: gongwen-writing
description: Use when user asks to write, rephrase, or edit Chinese government official documents (公文), or when processing text into formal party/government document style
```

### 触发场景

- 用户提到"公文"、"改写为公文"、"正式文体"
- 用户要求将口语化文字转为官方文件风格
- 用户提供 Word/PDF 文件要求按公文规范修改
- 用户需要撰写通知、报告、请示等特定文种

---

## 工作流程

```
用户输入（文本 / 文件路径）
  → 识别输入类型（纯文本 / Word / PDF）
  → 如为文件：使用 Read 或 office-mcp 读取内容
  → 分析内容，建议最合适的公文文种
  → 向用户展示建议，等待用户确认文种
  → 按确认的文种和公文规范改写/撰写
  → 询问用户输出方式（终端显示 / 导出 Word）
  → 按选择输出结果
```

### 异常处理

- 文件无法读取（损坏、加密等）：提示用户直接粘贴文本内容
- 内容过短或无法判断文种：询问用户期望的文种

### 交互节点

1. **文种确认**：skill 分析输入内容后，建议1-2个最合适的公文文种，用户确认或指定
2. **输出方式选择**：终端直接显示 或 导出为 Word 文档（使用 word-document-processor）

## 公文规范参考（内嵌于 SKILL.md）

### 规范基础

- 《党政机关公文处理工作条例》（中办发〔2012〕14号）
- 《党政机关公文格式》（GB/T 9704-2012，最新审查确认仍有效）

### 15种法定公文

| 文种 | 适用场景 |
|------|----------|
| 决议 | 经会议讨论通过的重要决策事项 |
| 决定 | 对重要事项作出决策和部署 |
| 命令（令） | 公布行政法规和规章、宣布施行重大强制性措施等 |
| 公报 | 公布重要决定或重大事项 |
| 公告 | 向国内外宣布重要事项或法定事项 |
| 通告 | 在一定范围内公布应当遵守或周知的事项 |
| 意见 | 对重要问题提出见解和处理办法 |
| 通知 | 发布、传达要求下级机关执行和有关单位周知的事项 |
| 通报 | 表彰先进、批评错误、传达重要精神和情况 |
| 议案 | 各级人民政府按法定程序向同级人大或其常委会提请审议事项 |
| 请示 | 向上级机关请求指示、批准 |
| 批复 | 答复下级机关请示事项 |
| 报告 | 向上级机关汇报工作、反映情况、回复询问 |
| 函 | 不相隶属机关之间商洽工作、询问和答复问题等 |
| 纪要 | 记载会议主要情况和议定事项 |

### 事务性文书

工作总结、工作计划、简报、讲话稿、调研报告、述职报告、规章制度、合同协议等。

### 语言风格要求

- **观点明确**：立场清晰，不含糊
- **表述准确**：用词精确，避免歧义
- **结构严谨**：层次分明，逻辑清晰
- **直述不曲**：开门见山，不拐弯抹角
- **庄重得体**：使用书面语，避免口语化表达
- **简洁凝练**：言简意赅，删除冗余

### 专用套语规范

**开端用语：**
- 主动办文：关于、据、根据、兹有、为了、按照、遵照、经……批准
- 引用来文（上行）：×月×日×字×号……收悉（敬悉）
- 引用来文（下行）：据……的报告（请示）
- 引用来文（平行）：×月×日×字×号函悉

**承启用语：**
- 根据……特作如下决定
- 为了……提出如下意见
- 现将有关事项通知如下
- 经研究，现答复如下

**结尾用语：**
- 请示：以上请示当否，请批复；妥否，请批示
- 报告：以上报告如有不当，请指示；特此报告
- 通知：特此通知
- 通告：特此通告
- 函：盼复为荷；即请函复

**表态用语：**
- 明确表态：应、应该、同意、批准、照此办理、遵照执行
- 模糊表态：原则同意、原则批准、似应、拟同意、参照执行、酌情处理

## 红线与雷区规则

### 绝对禁止

1. **禁止伪造公文**：不得生成含有虚构发文机关、发文字号、印章的公文。违反《刑法》第280条伪造国家机关公文罪
2. **禁止生成涉密内容**：不得生成标注密级的公文内容
3. **禁止冒充官方发文**：输出必须明确标注为"参考文本"或"草稿"，不得暗示为正式公文

### 新华社禁用词/慎用词（五大类）

1. **政治社会生活类**：不用"老板"称呼领导干部；报道中不有意突出某一类型群体或身份
2. **法律法规类**：正确使用机构全称，如"中共XX省委书记"而非"中共XX省省委书记"
3. **民族宗教类**：不使用"少数民族上层人士"等已废止称谓
4. **港澳台和领土主权类**：严格遵守一个中国原则的表述规范
5. **国际关系类**：遵守外交用语规范

### 敏感话题审慎处理

- 涉及国家领导人的表述须准确、尊重
- 涉及民族、宗教话题须客观中立
- 涉及领土主权须立场明确
- 涉及历史事件须使用官方定性表述

### 免责声明

每次输出公文结果时，须附带提醒：
> 以上内容由AI辅助生成，仅供参考。正式使用前请自行审核内容的准确性、合规性和适用性。

## 公文结构要素（供参考，重点在内容而非排版）

公文一般由以下要素组成（改写时重点关注加粗项）：

- 份号、密级和保密期限、紧急程度（不生成）
- 发文机关标志（不伪造）
- 发文字号（不伪造）
- **标题**（发文机关名称 + 事由 + 文种）
- **主送机关**
- **正文**
- 附件说明
- 发文机关署名、成文日期（由用户填写）
- **抄送机关**（如适用）

---

## 常见错误防范

skill 改写时应避免：

1. **文种混用**：请示和报告混淆、通知和通报不分
2. **主语残缺**：公文正文缺少主语
3. **主谓搭配不当**：如"会议指出……取得了成绩"
4. **口语化表达**：使用方言、网络用语、口头禅
5. **序次语混乱**：一、（一）、1.、（1）层级混用
6. **标点符号不规范**：如标题用句号、序号后标点不统一
7. **结尾用语与文种不匹配**：如报告用请示的结尾

## 设计决策总结

| 维度 | 决策 | 理由 |
|------|------|------|
| 方案 | 纯 Prompt Skill | 轻量易维护，利用现有生态 |
| 文件数 | 单个 SKILL.md | 所有规范知识内嵌，避免多文件复杂度 |
| 输入 | 文本 / Word / PDF | 覆盖用户主要使用场景 |
| 输出 | 终端 或 Word（用户选择） | 灵活适配不同需求 |
| 文种覆盖 | 15种法定 + 事务性文书 | 全面覆盖 |
| 规范基础 | GB/T 9704-2012 + 公文处理条例 | 权威国家标准 |
| 红线机制 | 禁伪造 + 禁用词 + 审慎处理 + 免责声明 | 合法合规 |
| 安装目标 | 可发布 skill 包 | 便于分享 |
